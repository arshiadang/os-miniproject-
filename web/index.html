One radio, many messages: who goes first?
Exp 6 · CPU scheduling: SJF and Round Robin

    
The AI picked messages to send, but the satellite has only one radio, so messages must wait in a line.
      We compare two rules:
      Shortest first (SJF: the quickest message always goes next) and
      Take turns (Round Robin: every message sends for a few seconds, then lets the next one go).

OS idea used: the mutex (lock) lets only one thread change the box at a time.
      Semaphores count free and filled slots, so sensors wait when the box is full and the radio waits when it is empty.
      Without the lock, the demo starts all sensors together so two can grab the same number at the same moment. That is a race condition.

Sharing power without getting stuck
Exp 9 · Deadlock avoidance with the Banker's algorithm

    
Four tasks share the satellite's things: 1 radio, 1 camera, 8 units of power (100 mW each) and 6 memory blocks.
      If we give away too much, tasks can end up waiting for each other forever. That is a deadlock.
      So before saying YES to a request, the satellite checks: "Can every task still finish?"

OS idea used: the Banker's algorithm, which is like a bank that only lends money if it can still pay everyone back.
      It pretends to say YES, then checks if the tasks can finish one by one (the safe sequence).
      If no order works, the answer is NO, because the request could cause a deadlock.
