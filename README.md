# SomaiyaSat OS Mini Project (KJS-SRS-01)

**Use case:** SomaiyaSat & SomaiyaPod – a PocketQube satellite with one radio that must decide what to transmit (telemetry, SSTV images, voice/data).
**Experiments:** 4, 6, 7 and 9, all applied to that satellite.

| Exp | What it does in this project |
|---|---|
| **4** System calls | A parent process creates 3 child processes: get telemetry → AI decides what to send → write a report (`fork`, `exec`, `waitpid`, `open`, `read`, `write`, `close`) |
| **6** SJF & Round Robin | Schedules the downlink jobs of one ground pass on the single radio (burst time = radio airtime) |
| **7** Semaphores & mutex | 3 sensor threads share a small 3-slot buffer with the radio thread (producer–consumer). The unsafe mode removes the mutex to show the race condition |
| **9** Banker's algorithm | Satellite processes request the transmitter, camera, power and memory; safe requests are granted, unsafe ones are denied |
| **AI part** | A small decision tree (scikit-learn) decides what to transmit. It is trained on synthetic data and has a safety rule: battery below 20% means beacon only |

| **Website** | A simple simulator page (`web/`). It walks through one satellite pass in 4 steps, runs the real programs above, and shows what happens line by line. You can pick normal or error inputs |

> All data is **synthetic** (generated by the Python scripts). This is an educational software prototype; no real satellite or radio hardware is used.

## How the parts connect

```
           ai/train_model.py  (run once) ──> data/model.pkl
                                                   │
EXP 4  ./exp4/mission  (parent process)            │
   ├─ child 1: python3 ai/generate_pass.py ──> data/telemetry.csv
   ├─ child 2: python3 ai/router.py  ──────> data/decisions.csv   (AI picks TX_TTC / TX_SSTV / TX_VOICE / SAFE_BEACON / IDLE)
   └─ child 3: C read()/write()  ─────────> logs/mission_report.txt

EXP 6  the chosen jobs compete for ONE radio      -> SJF vs Round Robin
EXP 7  sensors fill a shared buffer, radio empties it -> semaphores + mutex
EXP 9  jobs need TX, camera, power, memory        -> Banker's algorithm

WEBSITE  web/server.py runs the programs above and web/index.html shows the results
         (Exp 6 can take its jobs straight from the AI's decisions in Exp 4)
```

# STEP-BY-STEP: from installation to running

## Step 1 – Open an Ubuntu terminal

- **Ubuntu laptop / lab PC:** press `Ctrl + Alt + T`.
- **Windows laptop:** open **PowerShell as Administrator** and run `wsl --install -d Ubuntu-24.04`. Restart, open **Ubuntu** from the Start menu and set a username and password.
- **VirtualBox:** install Ubuntu 22.04 or 24.04 in a VM with 2 CPUs and 4 GB RAM, then open Terminal.

## Step 2 – Install what the project needs (one command)

```bash
sudo apt update
sudo apt install -y build-essential python3 python3-sklearn unzip
```

| Package | Why |
|---|---|
| `build-essential` | `gcc` C compiler and `make` |
| `python3` | runs the AI scripts |
| `python3-sklearn` | scikit-learn for the decision tree (also installs numpy) |
| `unzip` | to open the project zip |

Check:
```bash
gcc --version
python3 -c "import sklearn; print('sklearn', sklearn.__version__)"
```
If the second command fails, use this fallback instead: `sudo apt install -y python3-pip && pip3 install scikit-learn --break-system-packages`

## Step 3 – Get the project into your home folder

```bash
cd ~
unzip ~/Downloads/somaiyasat-simulator.zip -d ~
# On WSL, if the zip is in your Windows Downloads folder:
#   unzip /mnt/c/Users/<YourWindowsName>/Downloads/somaiyasat-simulator.zip -d ~
cd ~/somaiyasat-os
ls
```
**Run every command below from inside `~/somaiyasat-os`.**

## Step 4 – Train the AI model (once)

```bash
python3 ai/train_model.py
```
This creates `data/train.csv` (5000 synthetic rows) and `data/model.pkl`. Expected output: **Accuracy ≈ 0.95**, plus a classification report and confusion matrix.

How the AI works: each row describes the satellite's situation (signal strength, battery, time left in the pass, and how many TT&C / SSTV / voice items are waiting). The label is the correct action from `ai/rules.py`. A decision tree (max depth 8) learns to choose the action. 3% of labels are made wrong on purpose, like real noisy data.

📸 Screenshot: the training output.

```bash
make
```
That is the same as running these four commands:
```bash

gcc -Wall -o exp6/scheduler exp6/scheduler.c
```

## Step 6 – Open the website (the simulator)

```bash
make web
```
(same as `python3 web/server.py`). Leave this window open. It shows `running -> open http://localhost:8000`.

Now open **Chrome or Edge on Windows** and go to **http://localhost:8000**.

The page tells the story of **one 10-minute pass** of the satellite in **4 steps**, from top to bottom.
Every step works the same way: **① pick a situation (or click a suggestion) → ② press the blue button → ③ watch what happens, one line at a time.**

| Step | Story | Normal input | Error inputs to try (red ⚠ suggestions) |
|---|---|---|---|
| **1 · Satellite flies over** (Exp 4 + AI) | Main program starts 3 child processes: read sensors → AI decides what to send → write report | Normal day (battery 85%) | Low battery 15% (safety rule → beacon only) · Broken sensor (→ SAFE MODE) · Battery 150% (impossible reading → SAFE MODE) |
| **2 · One radio, many messages** (Exp 6) | Messages wait for the single radio: *Shortest first* (SJF) vs *Take turns* (Round Robin) | Messages the AI chose in step 1, turn = 4 s | Turn = 0 s · a message that needs 0 s (both rejected) |
| **3 · Sensors share memory** (Exp 7) | 3 sensor threads + 1 radio thread share a 5-slot box | Use the lock | Remove the lock (readings sent twice / lost = race condition) |
| **4 · Sharing power safely** (Exp 9) | Before giving radio/camera/power/memory, check that every task can still finish | AI brain asks 1 power + 1 memory (YES) | Photo task asks 3 power + 2 memory (NO, deadlock risk) · Health task asks for the radio (WAIT) · Photo task asks 4 power (NOT ALLOWED) |

You can also type your own values (battery %, message times, turn length, request numbers).
**▶ Play all 4 steps** runs the normal inputs one after another.

Every step has **"Show the real Linux output"** at the bottom. It shows the exact command and what the C program printed, which proves the website runs the real experiments.

To stop the website, click the Ubuntu window and press `Ctrl + C`.

> If http://localhost:8000 does not open: stop the server, run `python3 web/server.py --any`, and open the second address it prints (for example `http://172.x.x.x:8000`).

## Step 6b – Experiment 4: processes and system calls

```bash
./exp4/mission
```
What you'll see:
1. The parent creates **child 1** with `fork()`. The child runs `python3 ai/generate_pass.py` via `execvp()` → `data/telemetry.csv` (60 rows, one every 10 s).
2. **Child 2** runs `python3 ai/router.py` → `data/decisions.csv` (the AI's choice for every time step).
3. **Child 3** is a fork without exec. It reads `decisions.csv` with `read()` and writes `logs/mission_report.txt` with `write()`.
4. The parent waits for each child with `waitpid()` and prints each exit status. Everything is logged in `logs/mission_log.txt` using `open()` and `write()`.

**Try a low battery:** `./exp4/mission --battery 15` (the AI may only send a beacon).

**Failure test (sensor failure):**
```bash
./exp4/mission --fail
```
Child 1 exits with status 1 and writes nothing. The router can't find the file and exits with status 2. The parent sees this and enters **SAFE MODE**, writing a beacon-only plan itself.

Optional, to see the system calls:
```bash
sudo apt install -y strace
strace -f -e trace=clone,execve,wait4 ./exp4/mission 2>&1 | grep -E "clone|execve|wait4"
```
(`fork()` appears as `clone()` in strace.)

📸 Screenshots: normal run, `--fail` run, `cat logs/mission_report.txt`, `cat logs/mission_log.txt`, `head data/decisions.csv`.

## Step 7 – Experiment 6: SJF and Round Robin

```bash
./exp6/scheduler exp6/tasks.txt 4 8 16
```
`exp6/tasks.txt` holds the downlink jobs of one pass. Burst = radio airtime. An SSTV image in Robot36 mode takes 36 s; the other times are estimates.

| Job | Arrival (s) | Burst (s) |
|---|---|---|
| T1 TT&C beacon | 0 | 2 |
| T2 Housekeeping dump | 0 | 6 |
| T3 SSTV image 1 | 1 | 36 |
| T4 Codec2 voice | 3 | 12 |
| T5 M17 data packet | 4 | 4 |
| T6 SSTV image 2 | 10 | 36 |
| T7 TT&C beacon (late) | 30 | 2 |

**Expected results:**

| Policy | Avg waiting time | Avg turnaround time |
|---|---|---|
| SJF | 17.14 s | 31.14 s |
| RR q = 4 | 24.86 s | 38.86 s |
| RR q = 8 | 26.00 s | 40.00 s |
| RR q = 16 | 29.43 s | 43.43 s |

**Invalid-input tests:**
```bash
./exp6/scheduler exp6/tasks_invalid.txt 4     # burst time 0 -> error
./exp6/scheduler exp6/tasks.txt 0             # quantum 0 -> error
```

**Conclusion for the report:** SJF gives the lowest average waiting time, but the late TT&C beacon (T7) waits behind a 36 s SSTV image. Round Robin with a small quantum sends it much sooner (turnaround 12 s with q = 4 vs 32 s with SJF). For a satellite, the best policy is TT&C at top priority and Round Robin for everything else.

📸 Screenshots: Gantt charts and tables, both error messages.

## Step 8 – Experiment 7: producer–consumer with semaphores and mutex

```bash
./exp7/buffer            # SAFE: semaphores + mutex
./exp7/buffer unsafe     # UNSAFE: mutex removed
```
- 3 producer threads (battery, temperature, camera) × 4 frames each. One consumer thread (radio). A buffer of 3 slots.
- `empty` semaphore = free slots, so producers wait when the buffer is full. `full` semaphore = filled slots, so the radio waits when it is empty. `mutex` lets only one thread change the buffer and frame counter at a time.
- **Safe:** 12 frames, 0 duplicates, 0 lost → `NO RACE CONDITION`.
- **Unsafe:** the first writes deliberately overlap, so frame numbers get duplicated and some are lost → `RACE CONDITION`.
- Every transmitted frame is listed in `logs/buffer_log.txt`.

📸 Screenshots: safe run, 2–3 unsafe runs, `head logs/buffer_log.txt`.

## Step 9 – Experiment 9: Banker's algorithm

```bash
./exp9/bankers
```
Resources: TX = 1 transmitter, CAM = 1 camera, PWR = 8 units of 100 mW (an 800 mW power budget), MEM = 6 blocks of 32 KB.

| Check | Result |
|---|---|
| Starting state | **SAFE**, sequence P2_VOICE → P3_AI_ROUTER → P0_TTC → P1_SSTV |
| SSTV asks for (0,0,3,2) during eclipse | **DENY**: it would leave 0 of everything, so it is unsafe |
| AI router asks for (0,0,1,1) | **GRANT**: still safe |
| SSTV asks for (0,0,3,2) again | **WAIT**: only 2 power units are free |
| SSTV asks for 4 power units | **ERROR**: more than its declared maximum |

To try your own numbers, edit the `max`, `alloc` and request arrays in `exp9/bankers.c`, then run `make` again.

📸 Screenshot: the full output.


## If something goes wrong

| Problem | Fix |
|---|---|
| `No module named sklearn` | `sudo apt install -y python3-sklearn` |
| `gcc: command not found` / `make: not found` | `sudo apt install -y build-essential` |
| `data/model.pkl not found` | `python3 ai/train_model.py` |
| `open log: No such file or directory` | you're not in the project folder → `cd ~/somaiyasat-os` |
| unsafe buffer shows no race | run it again; give your VM at least 2 CPUs |
| website doesn't open | keep the `make web` terminal running; try `python3 web/server.py --any` and open the address it prints |
| `Address already in use` | the website is already running in another terminal; use that one or close it |
| website buttons show "Program not found" | run `make` first, from the project folder |
